## 外部サービスの情報を取得するとき

- GitHub の情報を**読む**ときは `gh` ではなく `gh-ro` を使う。`gh-ro` は読み取り専用の
  Fine-grained PAT を注入するラッパーで、パーミッションのプロンプトなしに実行できる
- 変更を伴う操作（PR のマージ、secret の更新、リポジトリ設定の変更など）のときだけ
  素の `gh` を使う。こちらは従来どおりプロンプトが出る
- 許可されていないサブコマンドを叩くと stderr に許可コマンド一覧が出るので、
  それを見て読み取り系に言い換える
- `gh-ro api` は GET のみ。フィールドを渡す読み取りは `--method GET` を明示する。
  GraphQL は `gh-ro api graphql -f query='query{...}'` の形なら通る（mutation は拒否）

`gh-ro` はサンドボックスではなく事故防止のガードレール。実効的な境界は PAT の
スコープ側にあるので、「ラッパーを通したから安全」という前提で書き込み操作を
組み立てないこと。
